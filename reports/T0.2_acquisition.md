# T0.2 — Data acquisition and integrity

Status: complete for priority-one analysis inputs. Supplementary Note S1,
Supplementary Table S1.

The public KU Leuven Dataverse API was accessible. The immune RDS and deposit
READMEs were acquired through it, with version, exact byte sizes, source MD5
checksums and local SHA-256 hashes recorded in `data/MANIFEST.json`.
The source listing is saved as `reports/evidence/rdr-v8-metadata.json`.

Both clinical Table S1 workbooks were obtained unmodified: the Cell supplement
from the publisher CDN and the Cancer Discovery supplement from the publisher's
Figshare deposit. Workbook sheet names, headers and sample identities were
checked. All shared clinical fields agree. Their file hashes, source URLs,
licence status and source-specific verification levels are in the manifest.
Cell provides no checksum in the retrieved material: that workbook is marked
`hashed_only`, not checksum-verified. The Figshare workbook passed its published
MD5 and exact-size checks.

The initially reported approximate RDS sizes are replaced by exact source bytes.
Priority-two TME/malignant files and all spatial bundles remain undownloaded.

Acquisition deviations: the plan anticipated manual downloads, but public APIs
and publisher download URLs worked. The direct PMC workbook URL returned HTML
and was not accepted as a workbook. The Europe PMC supplement archive timed out;
its `.part` file is not an accepted input. The first Cell candidate was Table S2
and was excluded; the accepted source is `mmc1.xlsx`, worksheet `Sup_table_1`.

Clinical originals are stored outside Git with the other raw data rather than
duplicated under `data/clinical/`. No raw EGA sequencing data were requested.
